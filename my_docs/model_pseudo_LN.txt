What TransFusion does:

		Takes LiDAR point cloud → 3D backbone → BEV feature map
		Heatmap head on BEV features → class-specific heatmap predicting object centers per category
		Local maximum suppression → select top-K peaks across all classes
		Each peak position → ref_pts in 3D space (free, BEV is already top-down 3D)
		BEV feature at peak location + category embedding → query feature (input-dependent, category-aware)
		First decoder layer: queries cross-attend to LiDAR BEV features → initial bounding boxes
		Second decoder layer: queries cross-attend to image features → final predictions

What ViP3D does:

		Maintains 300 persistent query slots across frames
		Empty slots initialized from fixed nn.Embedding — same weights every frame regardless of scene content
		Queries fed into 6-layer transformer decoder cross-attending to 6 camera image features
		Hungarian matching assigns object identities to queries after detection
		Memory bank enriches active queries with temporal information from past 4 frames
		QIM updates query vectors via self-attention among active queries for next frame
		Active slots carry forward across frames enabling tracking
		Empty slots sit idle with fixed learned initialization until a new object is matched
		The proposed integration:

Fixed nn.Embedding initialization of empty slots replaced by TransFusion-style LiDAR heatmap initialization
Each frame: LiDAR point cloud → 3D backbone → BEV features → heatmap head → top-K peaks
Empty slots filled with: peak positions as ref_pts + BEV features + category embeddings as query vectors
Active slots (obj_idxes >= 0) completely unaffected — carry forward through QIM as before
All 300 queries (active + newly initialized empty) fed into ViP3D's existing 6-layer image decoder
ViP3D's image decoder plays the same role as TransFusion's second decoder layer
LiDAR heatmap init replaces both TransFusion's first decoder layer and ViP3D's fixed embedding
Full tracking pipeline — matching, memory bank, QIM — remains completely unchanged
Result: TransFusion's input-dependent query initialization combined with ViP3D's temporal tracking
